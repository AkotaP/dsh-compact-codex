# 工作原理

安装与配置见 [README](<../README.md>)，宿主生命周期与开发约束见 [实现说明](<internals.md>)。

安装和卸载脚本要求先停止使用目标 profile 的 DSH，确保没有其他 profile 编辑或插件管理操作，执行后再启动 DSH。脚本自有锁不共享宿主写锁，读后比较再 rename 也不是原子 CAS；dry run 的 `requiresExclusiveProfileAccess: true` 仅报告此前提。脚本拒绝写入符号链接或非普通文件形式的 profile 清单与 lockfile。该限制只针对脚本操作，不限制插件正常运行或宿主内禁用、卸载时的资源清理。

## 最小侵入接入

[宿主入口](<../lib/plugin.js>) 查找 agent 保留组合中实际使用的 `compaction` 服务，而不是按 preset 名称替换配置。[实例适配器](<../lib/integration.js>) 只接受 prototype 精确等于官方 `BasicCompactionEngine.prototype`、且未被其他逻辑设置实例级 `summarize` 的后端。自定义后端、子类和已被实例装饰的实现保留原行为。

适配只在该实例上安装可恢复的 `summarize()` 包装，不改官方类的 prototype，不重建 Basic 引擎。包装按 owner agent 分流：已登记 agent 使用代码生成交接信息，其他 owner 回退原方法。工具、预算提示与缓存观察注册在该 agent 的独立作用域中。

以下职责继续由官方 Basic 后端管理：

- 自动压缩触发、阈值与路由策略。
- 选择压缩区间及保留近期历史。
- 日志锁、工具配对、事务提交与收缩校验。
- `/compact` 命令的执行流程。

因此不能把安装插件理解为“所有 preset 都被改写”，也不能把一次压缩理解为“全部历史必然被交接替换”。默认压力路径仍可保留近期原文；实际范围由宿主选择。旧显式引擎中的压力压缩推迟逻辑不属于此宿主适配流程。

## 交接信息

[交接生成器](<../lib/index.js>) 不发摘要请求，而从已有会话事件与账本生成 `# 上下文交接` 检查点。内容包括：

1. 最新真人请求。
2. 上次助手最后回复。
3. 任务账本概览。
4. 最近动作及事件编号。
5. 文件工作集。
6. 更早的请求轨迹。
7. 任务起点。

真人请求以事件来源区分，不将运行时上下文、技能目录等注入消息当作请求。动作列表按旧到新排列，记账、历史读取和换窗等自指操作不作为实际工作进度。文件工作集优先采用工具结果的差异元数据，否则从受支持的写调用参数提取路径，不能作为文件实际修改的独立证明。

`handoffTokens` 默认 20000，采用估算预算与分段裁剪，不是严格 token 上限。较低优先级的动作、文件和请求轨迹可能被省略，保底内容也可能超过预算。交接不能保证信息无损；缺失细节需要按编号回查，前提是原事件仍可读取。

交接前尝试将未记账工具动作保存为自动快照。快照只标记记录覆盖边界，不证明某个任务已经完成；快照写入失败会记录诊断，不能将其解释为进度已可靠保存。

## 主动换窗与预算提示

`new_context` 的执行分为登记与消费：

1. 工具检查会话、最近换窗和账本门槛，登记请求，不在工具执行中直接压缩。
2. `agent/pre-step` 先取得下游决策；步骤被拒时不消费，取消时停止处理。
3. 消费前重新检查账本和压缩边界；若下游已经压缩，不重复消费旧请求。
4. 在 turn 内调用官方 `compactRegion()`，保留系统头；事务与有效性仍由后端负责。

工具返回登记结果不表示换窗成功，后续应以压缩事件为准。`/compact` 不被替换，也不需要改为使用该工具。

`budgetContext` 默认关闭，关闭的是带数字的诊断读数，不是官方自动压缩。阈值提示与可选读数在允许执行的步决策中追加，不修改持久历史前缀。默认宿主适配不覆盖 `compactIfNeeded()`，不能承诺每次自动压缩前都会留一步等待模型记账。

## 任务账本与历史

[账本实现](<../lib/ledger.js>) 用 `task_id` 关联进度，状态可为 `in_progress`、`done`、`superseded` 或 `blocked`。`next_step` 表达下一步，`done_when` 表达验收条件，`anchors` 保存可定位的文件片段。

- `done` 需要能核对的成功工具结果事件编号；助手文字或工具调用本身不能替代成功结果。
- 文件锚点需能唯一定位，无法确认的锚点不作为有效定位依据。
- `ledger_append` 持久化失败应返回错误，不能报告写入成功。
- `ledger_read` 的 `current` 视图只显示当前窗口记录；概览和搜索用于跨窗口回查。

账本保存在 `$DSH_HOME/dsh-compact-codex/sessions/<session-id>/ledger.jsonl`，不直接加入会话事件流。主动换窗在账本非空时检查当前请求后的新鲜度，以及最近记账之后的未记录工具结果数量。当前窗口没有新真人请求时只略过请求新鲜度条件，仍检查未记录尾部；账本为空时不阻止首次换窗。官方压力压缩不被这些工具门槛阻断。

`history` 直接读取宿主会话事件，不另存历史副本：`search` 按词、角色、工具名、路径或窗口过滤；`read` 按事件编号分页，`field: "input"` 可读取原调用参数。检查点中的 `#编号` 是事件 `seq`。被压缩事件仍在可读日志中时可以检索，但这不等于所有原文会自动恢复到新窗口。

## 缓存观测、保活与冷缓存换窗

[缓存状态机](<../lib/cache.js>) 结合 provider 的缓存读写量和本地 TTL 假设估计前缀冷热。已有 baseline 的重复观测不能用每步当前时间续命；明确的缓存零值、路由变化及前缀收缩会重置相关判断。TTL 不是 provider 承诺，诊断读数不保证真实命中或精确费用。

**保活默认关闭（`keepalive: false`）。** 显式开启后，空闲期间可能发送真实模型请求并产生费用。调度检查 agent 忙闲、缓存前缀规模、空闲次数预算和连续失败次数，避免在忙碌或缓存已冷时继续保活；工具定义需与请求一同保留，以减少前缀差异。禁用或卸载时清理计时器并取消在飞请求，但已经发送的请求不保证能撤销计费。

**冷缓存换窗默认关闭（`coldSwitch: false`）。** 显式开启后，在步边界检查缓存状态、上下文规模与账本门槛，成立时调用 `compactRegion()`。交接本身不发模型请求；接下来的正常推理仍会消耗额度。该策略改变可见历史，不能表述为没有信息风险或总能节省成本。

## 浏览器显示与配置

[客户端](<../lib/client.js>) 只匹配来源为 `compact-checkpoint`、且正文包含插件交接标题的检查点。普通消息和其他后端的压缩行不被全局隐藏。样式、事件定义和槽位注册随插件生命周期释放。客户端为手写浏览器 bundle，无额外构建步骤。

配置表单位于设置 → 插件 → 本插件详情页，使用 `plugins.bundle.config` 槽位与 `configForms` 保存整个 `options` 对象。配置服务缺失或只读时不得影响交接渲染；保存成功、失败及等待状态均应显示。截图仅是预览，实际宿主与浏览器行为需要另行验收。
