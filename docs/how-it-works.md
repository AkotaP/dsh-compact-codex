# 工作原理

安装与配置见 [README](<../README.md>)，宿主生命周期与开发约束见[实现说明](<internals.md>)。

安装和卸载脚本要求先完全退出使用目标 profile 的 DSH，停止其他 profile 编辑和插件管理操作，执行后再启动。脚本锁只防止本安装器并行执行，不能阻止宿主或编辑器写入；写回前的内容检查与重命名之间仍有竞态。dry run 的 `requiresExclusiveProfileAccess: true` 只说明需要独占访问。脚本拒绝写入符号链接或非普通文件形式的 profile 清单与 lockfile。插件正常运行、宿主内禁用或卸载时的资源清理不需要为此退出 DSH。

## 接入范围

[宿主入口](<../lib/plugin.js>) 查询每个 agent 实际使用的 `compaction` 服务，而不是按 preset 名称替换配置。[实例接入逻辑](<../lib/integration.js>) 只接受 prototype 精确等于官方 `BasicCompactionEngine.prototype`、且没有自有 `summarize` 属性的后端。自定义后端、子类及已有实例级摘要改动保持原行为。

插件在符合条件的实例上包装 `summarize()`，为已登记 agent 生成交接；其他 owner 调用原方法。若实例没有自有 `compactIfNeeded()`，也包装该方法，提供下文的压前记账提醒。不改官方 prototype、不重建引擎、不覆写 preset。工具、预算提示和缓存观测注册在各 agent 的独立作用域中。

以下职责仍由官方 Basic 后端管理：

- 自动压缩触发、阈值与路由策略。
- 压缩区间选择及近期历史保留。
- 日志锁、工具配对、事务提交与压缩结果校验。
- `/compact` 命令的执行流程。

默认压力路径可因压前提醒推迟一次步边界（余量不足时不推迟），但阈值不变。一次压缩不一定用交接替换全部历史；默认压力路径仍可保留近期原文，实际范围由宿主选择。

## 交接信息

[交接生成器](<../lib/index.js>) 从已有会话事件与账本生成 `# 上下文交接` 检查点，不发起摘要模型请求。内容按以下顺序排列，缺失的部分省略：

1. 最新真人请求。
2. 上次助手最后回复。
3. 任务账本概览。
4. 最近动作及事件编号。
5. 文件工作集。
6. 更早的请求轨迹。
7. 任务起点。

真人请求按事件来源区分，不包括运行时上下文或技能目录等注入消息。动作按旧到新排列，记账、历史读取和换窗等操作不当作实际工作进度。文件工作集优先采用工具结果的差异元数据，否则从受支持的写调用参数提取路径；路径列表本身不能证明文件实际修改成功。

`handoffTokens` 默认 20000，是估算预算，不是严格 token 上限。内容先按各段限制裁剪；超出总预算时依次省略动作、文件和请求轨迹。最新请求、任务起点、账本概览和最后回复仍保留在交接中，但这些内容本身也可能经过裁剪，保底内容可能超出预算。交接不是无损记录；缺失细节需按事件编号回查，前提是宿主原事件仍可读取。

交接前尝试将未记账工具动作保存为自动快照。快照记录覆盖到哪里，不证明任务已完成。快照失败会记录诊断；不能据此认定进度已保存。

## 主动换窗与压前提醒

`new_context` 先登记请求，后在步边界处理：

1. 工具检查会话、最近换窗与账本条件，不在工具执行中直接压缩。
2. `agent/pre-step` 先取得下游决策。步骤被拒时保留请求，取消时停止处理。
3. 重新检查账本与压缩边界；若下游已压缩，不再处理旧请求。
4. 在 turn 内调用官方 `compactRegion()`，保留系统头；事务与有效性由后端校验。

工具返回已登记不表示换窗成功，应核对后续压缩事件。`/compact` 仍走官方流程，无需改用该工具。

`preCompactNudge` 默认开启。在官方 `compactIfNeeded()` 执行压力压缩前，若模型容量与用量可读、已达到阈值、推迟一步后仍不贴住窗口容量，且账本为空或不够新，则推迟本次压缩，在下游允许执行的步骤中追加记账提醒。推迟只改变这一次压缩的时机并注入记账提醒，压缩方式不变；没有余量时不推迟，压缩按官方时机立即执行，内容仍是本插件的交接信息，不会退回原生摘要。每个窗口最多推迟一次；之后不再因该提醒推迟，是否压缩仍由官方后端判定。溢出路径不推迟，提醒本身不调用模型。关闭此选项只关闭这次推迟，不改变官方阈值。

`budgetContext` 默认关闭，仅控制带数字的预算与缓存诊断读数，不关闭自动压缩或流程提醒。阈值提示和可选诊断追加到允许执行的步骤消息中，不改写持久历史前缀。

## 任务账本与历史

[账本实现](<../lib/ledger.js>) 用 `task_id` 关联进度，状态为 `in_progress`、`done`、`superseded` 或 `blocked`。`next_step` 记录下一步，`done_when` 记录验收条件，`anchors` 记录用于定位的文件片段。

- `done` 需要成功工具结果的事件编号；助手文字或工具调用本身不能代替成功结果，也不能单凭编号证明整个任务已完成。
- 文件锚点的匹配片段需唯一。相对路径按会话当前工作目录解析（优先宿主的工作目录服务，取不到时用会话头里的创建目录），绝对路径原样使用；会话头没有工作目录时才退回宿主进程工作目录。
- `ledger_append` 读/写失败都会返回错误，不报告写入成功；读取失败不会被当成空账本，以免下一次追加把整本记录覆盖掉。
- `ledger_read` 的 `current` 视图只显示当前窗口记录；概览和搜索用于跨窗口回查。

账本保存在 `$DSH_HOME/dsh-compact-codex/sessions/<session-id>/ledger.jsonl`，不直接加入会话事件流。主动换窗在账本非空时检查：当前窗口最近真人请求后是否记过账，以及最近记账后有多少工具结果未记录。没有新请求时只跳过第一项检查；空账本不阻止首次换窗；账本读取失败时拒绝换窗，避免把「读不到」当成「没有」。这些工具检查不会持续阻止官方压力压缩，压力路径只可能受到上述一次压前推迟。

`history` 读取宿主会话事件，不另存历史副本。`search` 可按词、角色、工具名、路径或窗口过滤；`read` 按事件编号分页，`field: "input"` 读取原调用参数。检查点的 `#编号` 是事件 `seq`。被压缩事件仍在可读日志中时可检索，但不会自动将全部原文恢复到新窗口。插件不删除历史，不代表宿主日志永久保留或始终可读。

## 缓存观测、保活与冷缓存换窗

[缓存逻辑](<../lib/cache.js>) 根据 provider 缓存读写用量和本地 TTL 假设估计前缀冷热。重复读取同一用量记录不会延长有效期；明确的零缓存用量、缺失用量、路由变化或前缀收缩会重置相关判断。TTL 不是 provider 承诺，诊断不保证真实命中或精确费用。

**保活默认关闭（`keepalive: false`）。** 开启后，空闲期间可能发送真实模型请求并产生费用。每次检查会核对忙闲状态、缓存前缀规模、有效期、尝试次数预算和连续失败次数。`idleKeepaliveBudget: 0` 不发送保活；`keepaliveAfterMs >= cacheTtlMs` 时，到达保活时间前已被判定过期，也不发送。

保活请求保留工具定义以减少前缀差异，并设 `maxTokens: 1` 限制输出；这不表示总计费只有 1 token，也不保证命中缓存。`checkEveryMs` 只控制开启保活后的后台检查周期。禁用或卸载时清理计时器并取消在飞请求，但已发送请求不保证撤销计费。

**冷缓存换窗默认关闭（`coldSwitch: false`）。** 开启后，在允许执行的步边界检查是否有可用缓存观测、是否达到假设的 `cacheTtlMs`、上下文是否达到 `coldMinTokens`，以及账本检查是否通过。若下游已压缩则跳过；条件成立才调用 `compactRegion()`。它与保活共用 TTL 假设，不由 `checkEveryMs` 计时触发。交接本身不发模型请求，但后续正常推理仍消耗额度；换窗会缩减模型可见历史，不保证无损或总能节省成本。

## 浏览器显示与配置

[客户端](<../lib/client.js>) 只匹配来源为 `compact-checkpoint`、且包含插件交接标题的检查点，不全局隐藏普通消息或其他后端的压缩行。样式、事件定义和槽位注册随插件生命周期释放。客户端为手写浏览器 bundle，无额外构建步骤；是否自动加载更新仍取决于宿主热更新能力，不能据此保证保存即生效。

配置表单位于设置 → 插件 → 本插件详情页，使用 `plugins.bundle.config` 槽位与 `configForms` 保存整个 `options` 对象。配置服务缺失或只读时，交接渲染仍独立工作；表单显示等待、保存成功和失败状态。截图仅为预览，不代替真实宿主与浏览器验收。
